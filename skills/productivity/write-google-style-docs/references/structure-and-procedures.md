# Structure and procedures

## Titles and headings

- Use sentence case for document titles and headings.
- Give each page one descriptive, unique level-1 heading. Follow a logical hierarchy and don't skip heading levels.
- Start a task heading with a base-form verb: **Create an instance**.
- Use a noun phrase for a conceptual heading: **Instance lifecycle**. Don't default to an *-ing* form.
- Don't put links in headings. Avoid code items in headings when a descriptive noun works.
- Don't end a heading with a period. Use other punctuation sparingly.
- Define an unfamiliar abbreviation in the first paragraph after a heading if the heading must use it.
- Mark an optional task heading with **Optional:** at the beginning.

## Paragraphs and flow

- Put the most important information first and group related ideas.
- Give each paragraph one purpose. Split dense paragraphs before they become hard to scan.
- Use an introduction only when it adds context; don't restate the heading.
- Put prerequisites, permissions, costs, destructive effects, and other constraints before the action they affect.
- Prefer in-context help over a link when one or two sentences are enough.

## Lists

- Use a numbered list for a sequence and a bulleted list for nonsequential items.
- Use a description list for terms paired with explanations.
- Introduce a list with a complete sentence. Use a colon when the list follows immediately.
- Keep items parallel in grammar, logical category, capitalization, and punctuation.
- Start English list items with a capital letter.
- End complete sentences and items that contain verbs with punctuation. Omit end punctuation for single words, short noun phrases without verbs, code-only items, link-only items, and titles. If a mixed list looks inconsistent, rewrite it or punctuate every item.
- Make it clear whether readers need all items or can choose among them.

## Procedures

- Introduce a multi-step procedure with useful context and a complete sentence, such as **To configure logging, follow these steps:**
- Write a one-step procedure as one bulleted sentence. Don't manufacture a numbered list for one step.
- Start the first sentence of each step with an imperative verb. Use complete sentences and one principal action per step.
- For an optional step, start with **Optional:**, not **(Optional)**.
- State information in reader order: context or location, goal or condition, action, command, placeholder explanations, detail, output, and result.
- Put a result after its action. Put a justification after the action unless the justification is a prerequisite.
- Avoid repeating procedures. Link to the canonical procedure when repetition would create maintenance risk.
- If multiple methods work, prefer one method that is accessible, short, and familiar to the audience. Separate genuinely necessary alternatives with headings, pages, or tabs.
- Use nested ordered lists for substeps. Keep nesting shallow and split long steps.
- Use a complete menu path only for consecutive menu choices. Don't use it to join unrelated controls.

## Notices

Use notices sparingly; readers often skip them.

- **Note:** Add relevant but nonessential information that sits outside the main flow.
- **Caution:** Tell the reader to proceed carefully.
- **Warning:** Identify an action that can cause irreversible loss, security exposure, financial harm, or similar serious consequences.
- **Success:** Reserve for dynamic or interactive success states, not ordinary static documentation.

Keep prerequisites, required steps, expected results, and ordinary cross-references in the main flow. Avoid consecutive notices; reorganize the content instead.

## Tables

- Use a table only when readers need to compare repeated fields or exact mappings. Prefer prose or a list for simple information.
- Introduce the table in preceding text.
- Use concise, sentence-case column headings without end punctuation.
- Mark header cells semantically and assign row or column scope.
- Don't merge cells. Split a complex table rather than relying on multiple header layers.
- Sort rows in a logical order or alphabetically when no logical order exists.
- Don't communicate new information through color, images, or symbols alone.
- Avoid inserting a table in the middle of a numbered procedure.
