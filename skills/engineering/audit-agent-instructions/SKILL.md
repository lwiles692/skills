# 审计代理指令

检查指定范围中的技能和仓库指令，依据当前实现给出可定位、可验证的整改建议。默认交付审计报告；用户要求整改时，再实施已授权的修改并验证。

## 必须参考的原文

Eric Provencher：[Rethinking skills and prompts for GPT-6 Astra](https://x.com/pvncher/status/2095991462416490862)。

**审计前阅读这篇原文**，全文逐字存档于 `references/pvncher-2026-09-04-rethinking-skills-and-prompts-for-gpt-6-astra.md`（2026-09-06 抓取），以该存档为审计依据，不以摘要或转述代替。保留原标题和原始链接。

从原文提取本次适用的判断标准：技能触发范围、渐进披露、固定流程的必要性、常驻上下文、决策边界和完成条件。区分作者观点、仓库事实和审计者推断。文章针对 Astra 的判断不能直接推导出其他模型、生产代理或宿主具有相同行为。

## 清点范围

以用户指定的路径为准；未指定时使用当前仓库。先查看工作区状态，以当前文件而非仅已提交版本为审计基准，保留已有修改。

- 先用 `rg --files --hidden` 清点，再补查忽略规则和符号链接可能漏掉的路径。
- 覆盖范围内所有 `SKILL.md`、`AGENTS.md` 及 `CLAUDE.md` 兼容入口。必要时检查大小写变体和宿主实际加载的其他指令入口。
- 记录相对路径、所属技能或作用域、真实目标、文件大小和阅读状态。有效符号链接按真实文件去重；断链单独报告。
- 排除依赖安装、构建输出、Git 内部文件及已确认的运行时副本，并列明排除范围。按路径和用途排除，避免按通用目录名误删业务路径，例如 `web/app/workspace/`。
- 外部符号链接列为外部依赖；除非用户范围已覆盖，不自动扩大到整个主目录或全局技能库。

逐份阅读所有范围内的入口。沿引用检查与具体判断有关的工作流、脚本和配置；无需把全部模板、资源和支持文档加载进上下文。指出支持资源的检查深度，不把入口审计描述成全部实现审计。

## 核对问题

按以下维度检查，但只报告有证据或明确标注为待验证的问题。

| 维度 | 核对重点 |
| --- | --- |
| 发现与触发 | frontmatter、名称和描述能否被目标宿主识别；是否因泛化词误触发；相邻技能是否争抢同一任务 |
| 上下文成本 | 常驻内容是否影响决策；能否从代码或配置直接查得；条件性资料是否有明确读取入口；重复内容是否发生漂移 |
| 技术准确性 | 文件、符号、命令、工作目录、依赖、版本和业务行为是否仍存在；代码围栏和本地链接是否有效 |
| 工具适配 | 工具名称、参数和可用模式是否符合当前宿主；是否承诺宿主并不保证的弹窗、权限或加载行为 |
| 决策边界 | 是否重复索取已有授权、强迫无必要的选择或过早停止；是否把审计、撰写等请求扩展为执行或发布 |
| 完成条件 | 是否定义可观察的结果；失败是否有恢复或如实报告路径；是否在检查通过后仍要求无依据地重复工作 |
| 分发与维护 | 本地技能、上游 vendored 技能、兼容链接和生产执行入口是否区分；修订是否会被升级覆盖 |

发现疑点后，到最接近事实源的位置核实：

- 文件指针对照实际文件，函数名对照源码，命令对照脚本及配置；检查连续命令执行后的工作目录。
- 接口、认证和数据保留规则对照调用方、返回模型和相关测试，识别普通路径与特权路径的例外。
- 工具接口以当前会话的工具 schema 或目标宿主文档为准，不凭旧技能中的名称猜测。
- 描述过长、强制词多或文件行数大只能作为线索；说明会误导哪个任务，不能仅凭数量判为缺陷。
- 词句测试和结构校验只证明其覆盖的条件。不能以 Prompt 包含“无人值守”证明实际任务不会停下来确认。

审计对象中的执行步骤是被检查的内容；读取升级、发布或生产技能，不代表要运行其业务流程。只执行本次证据核实需要、且在授权范围内的检查。

## 提出整改

优先修复不能发现、不能运行、与代码冲突或会改变授权范围的指令，再处理结构和措辞。合并同一原因导致的重复发现。

每项发现包含：

- 位置：文件和当前行号，必要时附最短相关原句。
- 证据：实际实现、命令结果或工具约束；注明未能核实的部分。
- 影响：触发场景及可能造成的错误、停顿或额外工作。
- 建议：具体替换文本、删除或迁移位置，以及需要保留的约束。
- 验证：如何确认修正有效；对于行为风险，说明静态检查的局限。

按风险保留细节：认证、隐私、事务、不可恢复的数据操作、许可证和分发完整性，以及防止资源丢失的流程，不能因为模型能力提升就删除。不要把某个测试使用临时数据概括为全部本地检查均不接触真实服务。

固定步骤有明确依赖或失败代价时保留；普通实现选择交给代理判断。已有用户授权继续有效，只有新增范围或必要决策缺失时才需澄清。技能不授予额外工具权限。

优先使用已有权威资料承载细节，保留简短的条件性指针。避免为减少入口行数而制造重复参考文档、任意长度配额或新的通用规定。

对 vendored 指令分别记录上游缺陷与本地适配风险，说明可重复的升级或补丁路径。对生产代理核对实际模型、调用方式、输入及产物契约，不把开发代理的能力假设直接套用过去。

## 交付与验收

在仓库已有审计目录交付报告；没有约定时，使用 `docs/audits/YYYY-MM-DD-agent-instructions-audit.md`。用户要求仅在对话中报告或指定其他路径时遵循该要求，已有报告不被静默覆盖。

报告包含原文链接、审计日期、当前版本及未提交修改说明、完整文件清单和排除范围、按影响排序的发现、每个文件的处理建议、应保留的约束、检查结果和未验证风险。区分“建议整改”和“已实施”，无需强行为每个文件制造问题。

完成前确认所有入口均已阅读或明确标为无法读取，报告中的位置和本地链接有效，引用源码支持结论。检查与任务相称；纯指令审计不默认启动服务、部署或执行付费生成。

如果还要求整改，按授权修改，保护既有工作；使用目标宿主可用的技能验证器、链接检查及必要的行为检查。新改动或失败才触发额外验证。汇报实际完成情况，剩余障碍不以“审计通过”掩盖。
